# 官网与图片异步网络流程

工具箱和 CLI 继续调用 `PipelineRunner.run()`；它创建单次任务事件循环，执行 `run_async()`。已有事件循环的调用方使用 `await runner.run_async(request)`。同一 runner 不支持重叠任务。

## 请求与并发

新闻逐条推进、逐条提交检查点。默认官网广度优先导航逐层并发，沿用作品匹配、三层导航与 16 个相关页面预算；来源按输入顺序合并。同步来源适配器在有限线程中解析，通过桥接将 GET 请求交给共享异步客户端。历史数据库访问保留在协调者线程。

公共页面与图片各自复用 HTTPX 连接池，SocialData 使用独立客户端。重定向逐跳验证公开 URL，显式年龄确认 Cookie 仅发送给原域；响应头和实际解码字节均受大小限制。页面缓存忽略片段、区分 Cookie 状态，图库片段仍保留在来源证据中。只缓存成功响应，瞬时错误可在后续独立访问时恢复。

SocialData 同一帖子 ID 共享查询任务和结果，失败也不重查。关闭任务选项时查询数为零。密钥仍从凭据库在运行时读取，参数、日志、检查点和输出均不保存密钥。

## 配置

旧 TOML 缺少以下 `[network]` 字段时自动使用默认值；这些字段不参与检查点结果配置哈希。

| 字段 | 默认 | 含义 |
|---|---:|---|
| page_concurrency | 4 | 全任务页面 HTTP 并发 |
| page_per_host | 2 | 同域页面 HTTP 并发 |
| image_concurrency | 8 | 图片下载及待处理窗口 |
| image_per_host | 8 | 同域图片 HTTP 并发 |
| image_processing_threads | 2 | 图片验证、解码、哈希、质量分析线程 |
| socialdata_concurrency | 2 | SocialData 不同帖子查询并发 |

图片流写入临时 `.part` 文件，验证后原子替换。处理窗口最多容纳 `image_concurrency` 个文件，处理线程数限制 CPU 并发。保留既有筛选、新闻内去重、X 优先级、原件、审阅件和链接；无效 X 图片不因优先级绕过文件校验。

暂停阻止新 HTTP 派发，在途工作允许完成；停止取消网络等待和队列并移除未完成临时文件。同步兼容调用无法强制杀死第三方函数，关闭时等待其退出；视频下载实现保持原样，通过兼容线程调用。

## 评估

`runner.network_metrics` 给出页面/图片请求数、缓存命中、阶段墙钟耗时及图片处理线程累计耗时。累计线程耗时可重叠，不能与墙钟阶段直接相加。

`scripts/benchmark_async_network.py --mode local|real|all` 在独立子进程导入冻结原版及当前代码。本地服务使用受控延迟及冻结媒体；真实小样固定 `226_副本.docx` 中三条官网新闻，关闭搜索、LLM、视频和 SocialData。报告位于 `output/async_benchmark_20261002`，包含原版与异步版图片索引、来源与失败记录。
