# X 图片下载与恢复

## 共用入口

工具箱、CLI 的 `PipelineRunner.run()` / `run_async()` 使用同一下载链路。主目录快捷方式运行 `启动工具箱.pyw`，从本项目 `src` 加载代码，重启后即可使用修复。

`network.trust_env` 默认 `true`，传入同步与异步公共网络客户端，支持系统代理和证书配置；设置为 `false` 可直接连接。此字段同并发参数一样不参与检查点结果配置哈希。SocialData 客户端独立，密钥仅从凭据库读取；任务开关仍默认关闭。

## 原图与失败

X 照片仅对允许的 `https://pbs.twimg.com/media/` 地址补齐 `name=orig`，保留格式参数及旧 URL 对应候选身份。`media_source_url` 保存 API 返回地址，`downloaded_url` 保存实际响应地址，`expected_width` / `expected_height` 保存 API 的原图尺寸。

原图失败允许对原始媒体地址尝试一次降级，不增加查帖请求。非法 URL、超大响应和明确占位图不触发降级。所有下载均验证重定向和响应大小。失败说明非空，单图失败不能中断同批其他图片。

## 下载状态与持久化

候选的 `download_status` 为 `pending`、`downloaded`、`retryable_failed` 或 `permanent_failed`，独立于筛选状态。新字段均有默认值，旧索引可读取。成功恢复会清除下载失败派生标记。

下载前保存所有候选。单一结果消费流程原子更新 `media_state` 内的新闻清单，每秒合并检查点，在新闻结束和暂停／停止安全点立即提交。取消时保留已完成原件与逐图错误，清理未完成临时文件。

`x_media_cache` 保存白名单化的公开媒体响应以及待查询／失败标记，不保存密钥、请求头或用户私有信息。成功响应在返回来源采集器之前持久化，避免查询成功后取消导致再次付费。失败或未知请求不会自动重新查询；照片和视频仍复用一次响应。

检查点新增 `retryable_candidate_ids`、`x_query_count`、`media_cache_version`。新缓存协议为 1；旧断点默认 0，在缺少已查询媒体信息时保守提示，不自动重复查询。新协议能区分仅完成来源解析、尚未调用 API 的任务，允许正常续跑。

恢复只使用本任务内经过路径、哈希、解码验证的原件。已发布但有可重试或缺失图片的任务可继续恢复，不重新发现已有媒体来源。所有已有原件在发布前保全；清理暂存目录前核对索引及最终资产。

## 工具箱与验证

进度页显示 X 查询数、附件数、下载成功、待恢复及失败数。统计事件不会改变新闻进度、暂停状态或输出原始凭据。

验证使用 263 期缓存的 57 张照片和一次工具箱真实查询；视频、LLM 关闭。结果位于 `output/x_download_fix_20261006_180336`。后续恢复验证不再查询帖子或下载已有图片。

## Windows 清单占用恢复（2026-10-07）

Windows 的读取句柄如果不允许删除共享，`os.replace` 会返回 WinError 5；这不是图片请求失败。原子 JSON 写入对 5/32/33 做有限等待，其他错误继续上报。下载清单在目标长期被占用时保存独立恢复快照，保留原清单；续跑按任务身份、新闻 ID 与快照版本加载最新记录。协调器在线程中串行持久化，等待文件锁不会阻塞网络事件循环。

有新闻数据的失败检查点不再因“没有待补下载的图片”直接返回失败，仍可继续未处理的新闻或重做发布。完成通知在最终清单和检查点保存后发出。永久目录权限或存储故障仍明确失败，不伪报成功。
