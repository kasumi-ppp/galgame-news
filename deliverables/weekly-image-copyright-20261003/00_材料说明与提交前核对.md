## 当前判断

项目已经具备准备一件计算机软件著作权登记的技术基础：具有独立程序包、可操作的桌面界面，以及文档解析、来源发现、图片处理、审核、历史记录与导出流程。是否享有可登记的著作权，还需要申请人据实确认开发关系和权属，最终由登记机构审查。测试通过不等于登记获准。

本次核验的是当前工作目录，包含尚未提交的开发变更，不以某个 Git 提交代替真实交付状态。生产包共 73 个 Python 文件、13,351 个物理行、11,764 个非空行；统计包含注释，不包含测试、第三方库、历史脚本或本次材料生成代码。

中性命名源码副本相关回归：259 项通过，2 项跳过，0 项失败，覆盖数据模型、配置、图片筛选、导出、文档解析、审核、桌面界面、设置和任务存储。本次没有把全部原项目测试重新声明为副本的全量测试。另完成真实组件离线验证：示例 DOCX 解析出 2 条新闻，人工已选的 2 张演示图片成功导出，实际界面生成了 5 张操作截图。

尚未在本次核验中完成：真实外部站点联网采集、API 实际额度与可用性、干净 Windows 机器的独立安装包验证、任意行业输入的准确性评估。

## 材料内容

1. `01_申请信息填写稿.docx`：3 页。包含可转录到登记系统的技术字段、主要功能、技术特点和待确认的申请人字段。这不是官方申请表。
2. `02_用户操作与设计说明书.docx`：10 页。覆盖五个实际界面、输入格式、操作步骤、导出结构、恢复方式、模块与数据设计及功能边界。
3. `03_源程序鉴别材料.docx`：60 页。按确定的完整源码文件顺序生成，取前后各 30 页，每页 50 个非空展示行。
4. `04_示例周报.docx`：1 页。两条中性新闻，来源为保留示例域名，供理解格式与离线解析使用，不是实际采集结果。
5. 同名 PDF 是经过本机 Word 导出的定版预览。源程序 PDF 为 60 页，用户说明书 PDF 为 10 页。
6. `软件源码副本/`：与申请材料对应的可运行源码、配置和依赖声明，建议保留用于复现；无需将完整副本当成默认上传附件。
7. `源码文件清单.json`、`源码页码映射.json`：记录文件散列、行数、文件编排与交存页对应的源码位置，用于核验与更新材料；不是必需提交的申请附件。

## 名称和代码副本

申报全称统一为“周报图片采集与管理软件”，版本沿用代码声明的 V0.2.0，未虚构首次发布或新版本开发时间。业务描述围绕周报图片采集、筛选、人工审核和导出展开。

源码副本来自当前生产包，已机械调整历史产品品牌、Python 包名、请求客户端标识、线程前缀、应用数据与凭据服务命名，并将 CLI 默认输出位置改为当前目录下的 output。少量旧品牌词所在的匹配文本也随之替换。源码副本使用 `weekly_images` 包名；源程序鉴别材料和界面截图都基于该副本。原项目的生产文件没有因准备材料而改名或替换。

这是一份中性命名的软件材料副本，不是将原有业务规则改造为通用识别系统。原有专用分类、实体与来源适配逻辑仍存在，附加视频模块也保留在完整源码中。本次说明书真实限定为“符合既定结构的周报图片整理”，不声称已经覆盖所有行业或任意文档结构。

截图来自实际运行的 Qt 界面，新闻及配图均为自制离线演示素材，进度截图使用演示事件。没有使用第三方作品画面充当自主研发内容，也没有把演示素材描述为在线采集成功证据。

## 源程序材料的生成口径

程序文件按 `源码页码映射.json` 中的完整顺序排列，每个生产 Python 文件出现一次。为便于阅读，空白展示行被省略，长行按显示宽度折行；不删减任何被选中非空行的文本，完整可运行源码保留原有换行和缩进。前部取首 1,500 个非空展示行，后部取末 1,500 个非空展示行，共 3,000 行。页码映射中的 continuation 标记长源代码行的续行，可据此还原。

“每页50行”是排版展示行数，不等于每页50条独立语句，也不用于声称新增代码量。源码规模以文件清单的原始物理行计数为准。若登记系统或受理人员要求不同的代码行口径，应从同一副本重新排版，不应补写无意义代码。源程序不包含第三方库源码、真实 API 密钥或用户周报数据。
